## 91 — "could not reach github"

`Secrets.explain` turns a transport exception into:

> Could not reach GitHub. The phone may be offline — nothing was changed here.

**It stops the session on purpose.** A turn that keeps asking a network that is not answering burns a
request per tick and reports nothing new. The stop is the same ladder a refused key goes down: an error
that will not fix itself by being retried is one that needs the person.

If it fires when GitHub *is* reachable, that is a real bug and the trace will have the exception beside
the sentence — the `secrets` line in `session.log` keeps the original.

## 93 — what "before" should be for a clock preset

The current rule, from the operator's own earlier wording: *"previous interval is just start of the current
interval minus length of the current interval"*. It is the only rule that also works for a hand-set
interval, and it makes the comparison fair — two windows of equal length.

It is **wrong for a clock preset**, and this report is the case that shows it. "1 day" at 13:59 covers
00:00–13:59, which is fourteen hours of traffic. The period before it is a fourteen-hour slice starting at
10:01 the previous day — not yesterday, and not a period anybody thinks in.

The alternative for a clock preset is the **previous whole calendar period**: yesterday 00:00–00:00, last
week, last month. That is what a person means by "before" when they picked a clock interval, and it is
what the report asks for.

**The two rules must not be merged.** A hand-set interval has no calendar period to be "the previous" of,
so it keeps the length rule. This is a decision for the operator, not a silent change.
