# Pass 1 — the truth pass

What was measured, what was fixed, and what needs a ruling. Measured 2026-11-11 on `development`.

## The numbers, before and after

| measure | before | after |
|---|---|---|
| main Kotlin | 86 files · 50,337 lines | 84 files · 49,900 lines |
| comment share of main | 47.8% | 47.4% |
| `@Test` | 1,680 | 1,679 |

The comment share barely moved, and that is the honest result: most of it is the *why* the operator
asked for in earlier work. What was cut was the part that was **wrong** or **archaeology**.

## Fixed

### A test that could never fail
`ContextBudgetTest: a session log with no number keeps everything` had a body of pure comments. It now
writes two rows, calls `trimSession(0)`, and checks nothing was dropped — which fails if the
`limitTokens <= 0L` guard goes.

### `KeyVerdict` was written, documented, tested — and never called
`CredentialStore.token` deleted a stored token on **any** exception. `KeyVerdict` exists precisely to
tell a reset phone (the token can never open) from a locked one (it can, later), and its own test
comment describes this exact bug as historical. It was not historical: the caller never used it.

The decision is now `KeyVerdict.shouldDrop`, a function outside `CredentialStore` **because that class
takes a `Context` and a JVM test cannot build one** — which is how the bug survived. Both directions
are tested.

### `Probe` lost its only caller and the removal doc said otherwise
`c4977768` removed the model connection and left `Probe` behind. The removal document said *"the
connection check still exists for git; only its model branch went."* False: the git check is
`GitService.lsRemote` against the project's own address, a different mechanism for a different
question. Deleted, with `ProbeTest` and its test-map line, and the doc corrected.

### Two things in the main source set that only tests used
`ScriptedDoor` (the agent loop's test double) and `serverSentLines` (a one-line splitter). Both shipped
in the APK and no path could reach either. Moved to `app/src/test`.

### `Secret`, a protection nobody adopted
A value class whose whole point was that a token cannot be printed by accident. **Nothing constructed
it** — tokens travel as bare `String` through `CredentialStore`. A documented, tested guarantee that is
not in force is worse than none.

### Comments that described the previous version of their own command
- `browse` still promised `from`/`to` after losing them.
- `search`'s examples said `scope:` where the key is `path:`.
- `search`'s "why three commands became one" ran 14 lines re-quoting operator wording the code no
  longer matches.
- `Trace`'s class doc was 54 lines, 19 of them a changelog of the version before it.
- `AgentLog` explained a burst-ending mechanism that no longer exists.

## Verified, not changed

**All 20 agent commands dispatch exactly once and have exactly one handler.** `KEYS` (20), dispatch
branches (20), handler functions (20) — no orphan command, no orphan handler. The tool surface is
fully wired.

**All nine screens are reachable from `MainActivity`**, one call each.

**`tools/check-test-map.py` works.** It caught the stale `ProbeTest` line immediately, which is the
failure mode its own doc says is silent.

## Needs a ruling — not changed

### 1. `startAgent` and `stopAgent` have no caller in main
Only tests call `startAgent`. The app starts an agent by **speaking to it** (`AppViewModel:4055`
resumes a stopped session) and by the service ticking. `stopAgent` is called by a loop at `:4357` that
is itself called from nowhere.

So: is `startAgent` API-ahead-of-consumer (leave it), or is there a control that was meant to exist?
**I cannot tell from the code.**

### 2. 24 `AppViewModel` functions are never named in a UI file
Most are reachable — called from inside the view model. But this is the class that would benefit from
a reachability gate, and that is pass 2's job.

### 3. 50 functions over 90 lines; 6 files over 2,000
`AppRoot` 517 lines, `Dialogs` 432, `DrawingSurface` 312, `write` 259. This is pass 3, and it is
structural rather than cosmetic — `AppRoot` is a navigation god-composable.

## What pass 1 deliberately did not do

It did not restructure. Every change above is provable from the code alone: a declaration with no
caller, a comment contradicted by the line below it, a test that cannot fail. Nothing here needed a
judgement about what the app *should* be.
